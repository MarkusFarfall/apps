# Знакомая вода

Симулятор морской рыбалки: лодка, удочка, море на рассвете. Двенадцать акваторий, триста видов рыб,
пять портов, погода, сезоны и ежедневные задания. PWA: открывается на телефоне, играется в браузере.

**Стек:** Next.js 16 (App Router, Turbopack) · React 19 · TypeScript 5.9 · Tailwind CSS 4 ·
Postgres через Drizzle ORM · canvas-рендер сцены и WebAudio-звук.

**Играть:** https://water-import.vercel.app — прод собирается автоматически из ветки `main`
(проект Vercel `water-import`, Root Directory `projects/water-import`).

## Что есть в игре

| Раздел | Содержимое |
|---|---|
| **Мир** | 12 акваторий (бухта → бездна → ледяной шельф), по 3 точки лова в каждой, глубина до 2000 м |
| **Рыбы** | 301 вид в пяти томах кодекса: глубина, редкость, время суток, погода, сезон, фаза луны, вес, цена, сила, окраска, наживки, описание |
| **Варианты** | альбинос, золотая, трофейная, со шрамами, меланист — редкости с множителем цены |
| **Снаряжение** | 9 судов пяти классов, удочки/катушки/лески/крючки/соны, 10 наживок, доработки |
| **Прогрессия** | 60 уровней и звания, дерево перков, квесты, достижения, находки |
| **Экономика** | 5 портов со своим спросом, насыщение рынка, «горячая рыба дня», заказы клиентов, ночлег в тавернах |
| **Ежедневное** | задания со стриками и сундуками, погода, ветер, лунный цикл, события |

## Запуск локально

```bash
npm install
cp .env.example .env.local     # укажите DATABASE_URL
npm run dev                    # http://localhost:3000
```

Схема базы создаётся одним из способов:

```bash
node scripts/db-migrate.mjs                 # таблицы + политики доступа (повторный запуск безопасен)
# или: npx drizzle-kit migrate              # миграции из drizzle/ (DATABASE_URL из окружения или .env.local)
# или: выполнить supabase/schema.sql, затем supabase/security.sql в SQL-редакторе Supabase
```

Прод-сборка:

```bash
npm run build && npm start     # сборка не зависит от внешних CDN: шрифты локальные
```

## Подключение Supabase

1. Создайте проект в Supabase и скопируйте строку подключения
   (**Project Settings → Database → Connection string → Session pooler**).
2. Пропишите её в `.env.local` (локально) или в переменных окружения Vercel как `DATABASE_URL`.
3. Примените схему: `node scripts/db-migrate.mjs` (или вручную — `supabase/schema.sql`, затем
   обязательно `supabase/security.sql`: включает RLS и закрывает таблицы от публичного REST-API).
4. Проверьте `GET /api/health` — должно быть `{"ok":true,"db":"up"}`.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | строка подключения к Postgres. Нужна в рантайме: без неё `/api/health` отвечает `db: down`, а маршруты — 503. Сборка (`next build`) базы не требует |
| `SITE_URL` | публичный адрес для OpenGraph-ссылок; на Vercel подставляется автоматически |

## Аккаунты и сохранения

- **Гость** получает локальный профиль (`localStorage`, `zv_player_id`), прогресс пишется и в облако.
- **Регистрация** привязывает гостевой профиль к аккаунту — прогресс не теряется.
- Сохранение хранится и локально, и в базе: при входе с другого устройства берётся более свежее
  по `stats.playSeconds`, а попытка перезаписи старым сохранением отклоняется (`409` + актуальные данные).
- Пароли — scrypt с солью; в базе только SHA-256 от токена сессии, сам токен в httpOnly-cookie.
- Уловы пишутся в `catches` для мировых рекордов, рейтинги — в `leaderboard`.

## Проверка работоспособности

```bash
BASE_URL=http://localhost:3000 bash scripts/smoke.sh
```

Скрипт проходит весь путь: гостевое сохранение → регистрация → облачное сохранение → защита от
перезаписи → уловы и рекорды → рейтинг → вход со второго устройства → выход.
Тестовые данные после прогона удаляются (`node scripts/reset-test-data.mjs`).

## Деплой на Vercel

### Автоматически из GitHub (рекомендуется)

В репозитории есть workflow **«Знакомая вода — боевая база и деплой»**
(`.github/workflows/water-production.yml`). Он создаёт таблицы и политики в базе, публикует проект
на Vercel, дожидается ответа `/api/health` и прогоняет сквозные проверки по боевому адресу.

Один раз добавьте в **Settings → Secrets and variables → Actions**:

| Тип | Имя | Значение |
|---|---|---|
| Secret | `DATABASE_URL` | строка подключения Supabase (Connect → **Session pooler**, порт 5432) |
| Secret | `VERCEL_TOKEN` | Vercel → Settings → Tokens → Create |
| Secret | `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID` | необязательно; нужны, если проект на Vercel уже создан |
| Variable | `VERCEL_PROJECT` | имя проекта на Vercel (по умолчанию `water-import`) |
| Variable | `VERCEL_SCOPE` | команда/аккаунт Vercel, если их несколько (необязательно) |
| Variable | `SITE_URL` | публичный адрес для OpenGraph (необязательно) |

Дальше: **Actions → «Знакомая вода — боевая база и деплой» → Run workflow**. Каждый push в `main`,
затрагивающий `projects/water-import`, повторяет тот же процесс. Если нужно только подготовить базу,
у запуска вручную снимите галочку `deploy`.

### Вручную в панели Vercel

1. Импортируйте репозиторий `MarkusFarfall/apps`, **Root Directory** = `projects/water-import`.
2. Добавьте переменную окружения `DATABASE_URL` (строка Supabase).
3. Примените схему: `node scripts/db-migrate.mjs` (или `supabase/schema.sql`, затем `supabase/security.sql`).

## Заметки

- Шрифты (Cormorant Garamond, Inter) подключены локально через `@fontsource` — сборка и работа
  офлайн не зависят от Google Fonts.
- Иконка приложения — `public/icon.jpg` (1024×1024), на неё ссылаются манифест и OpenGraph.
- `BLOB`/S3 не используются: и сохранения, и рейтинги живут в обычном Postgres.
