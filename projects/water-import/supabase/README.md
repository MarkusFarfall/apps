# Подключение к Supabase

1. Создайте проект в Supabase и скопируйте строку подключения
   (**Project Settings → Database → Connection string → Session pooler**).
2. Пропишите её в `.env.local` как `DATABASE_URL` (пример — в `.env.example`).
3. Рекомендуемый путь: из `projects/water-import` запустите `npm run db:migrate` — команда безопасна при повторном запуске, применяет RLS и проверяет схему. В SQL Editor можно выполнить `supabase/schema.sql`, затем `supabase/security.sql`.
4. Перезапустите приложение и проверьте `/api/health` — ответ `{"ok":true,"db":"up"}`.

Отдельные миграции Drizzle Kit не используются: старый набор не включал `rate_limits` и политики RLS.

## Что хранится

| Таблица    | Назначение |
|------------|------------|
| `users`       | учётные записи: имя пользователя и хэш пароля (scrypt) |
| `sessions`    | активные входы; хранится только SHA-256 от токена, сам токен — в httpOnly-cookie |
| `players`     | игровой профиль, привязанный к аккаунту (гостевого режима нет) |
| `saves`       | полное сохранение (JSON) и поля для рейтинга |
| `catches`     | журнал уловов для мировых рекордов |
| `rate_limits` | общие между инстансами счётчики ограничения частоты запросов |

## Безопасность

- пароли — scrypt с солью, сравнение за постоянное время;
- сессии — 30 дней, скользящее продление, выход со всех устройств при смене пароля;
- ограничение частоты попыток входа и регистрации;
- проверка источника запроса (защита от CSRF) для всех изменяющих запросов;
- сохранения аккаунта может читать и писать только его владелец;
- защита от перезаписи более свежего прогресса с другого устройства;
- фильтр нецензурных имён в профилях и рейтингах;
- RLS закрывает таблицы от публичного API Supabase.
