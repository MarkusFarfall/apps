# ДМБ Таймер

Дембельский таймер с точностью до секунды. Устанавливается на телефон как обычное приложение (PWA) и работает офлайн.

**Живая версия:** https://dmb-timer.vercel.app

## Что умеет

| Раздел | Содержимое |
|---|---|
| **Таймер** | обратный отсчёт до дембеля до секунды, табло (Board) для показа на экране |
| **Стата** | проценты, часы, оставшееся время, прогресс по этапам службы |
| **Календарь** | разбивка срока по месяцам и дням, отметки и заметки по дням |
| **Сантиметр** | «сантиметр» дембеля — визуальная шкала срока |
| **Медали** | достижения: «Первый шаг», «Первые сутки», «Экватор», «100 дней в строю», «Миллион секунд» и другие |

Дополнительно: онбординг при первом запуске, профиль (дата начала и конца службы, имя), 6 тем оформления
(Хаки, ВДВ, Флот, Погранцы, Ночной наряд, ВКС), режим табло, «поделиться» итогом, настройки (миллисекунды, единицы, виброотклик).
Есть цитаты и распорядок дня — зависят от времени суток.

## Стек

- **Vite 7** + **React 19** + **TypeScript 5.9**
- **Tailwind CSS 4** через `@tailwindcss/vite`
- `vite-plugin-singlefile` — вся сборка инлайнится в один `dist/index.html`
- `canvas-confetti` (салют по достижениям), `lucide-react` (иконки), `clsx` + `tailwind-merge`

## Push-уведомления

Настоящие Web Push: приходят при закрытом приложении, работают на Android, десктопе и на iPhone
(iOS 16.4+, если приложение добавлено на экран «Домой»).

### Что приходит

| Уведомление | Когда |
|---|---|
| 🏆 Достижения | в момент события: «Первый шаг», «Экватор», «100 дней в строю», «Неделя до ДМБ» — всего 24 медали |
| 🎯 «Каждые N дней службы» | в начале дня, когда число полных дней службы кратно N (N = 5, 10 или 30; можно выключить) |
| ✅ «Проверка связи» | по кнопке в настройках — чтобы убедиться, что всё работает |

Тексты уведомлений содержат процент срока, остаток дней и текущее звание. Пока приложение открыто,
медаль дополнительно показывает системное уведомление в тот же момент; когда закрыто — за это
отвечает серверный планировщик.

### Как это устроено

```
браузер ──подписка (PushSubscription)──▶ POST /api/subscribe ──▶ Vercel Blob (приватное хранилище)
   ▲                                                                        │
   │                                                              GET /api/cron (по расписанию)
   └──────────── push через web-push (VAPID) ◀── dueNotifications(schedule, окно) ┘
```

- **Логика событий живёт в одном месте** — `src/lib/notify.ts`. Её использует и приложение
  (предпросмотр «что придёт дальше» в настройках), и серверная функция (`api/cron.ts`),
  поэтому правила не расходятся.
- **Идемпотентность.** У каждого события есть ключ (`ach:p50`, `days:20`). Отправленное
  запоминается в подписке, поэтому повторы исключены даже если планировщик запускать чаще.
- **Мёртвые подписки** (404/410 от push-сервиса) удаляются автоматически.
- **Точность.** Событие привязывается к своей минуте: медали — к точному моменту, периодические
  напоминания — к локальной полуночи дня по часовому поясу пользователя.

### Настройки в приложении

Экран «Настройки → Уведомления»: включение push, тумблер достижений, интервал «каждые N дней»,
предпросмотр ближайших трёх уведомлений и кнопка проверки.

### Требования к окружению

| Переменная | Назначение |
|---|---|
| `VAPID_PUBLIC_KEY` | открытый ключ VAPID (серверная часть) |
| `VAPID_PRIVATE_KEY` | секретный ключ VAPID — только в переменных окружения Vercel |
| `VAPID_SUBJECT` | контакт для push-сервисов, `mailto:…` |
| `CRON_SECRET` | защита `/api/cron`: Vercel сам подставляет `Authorization: Bearer <CRON_SECRET>` |
| `BLOB_READ_WRITE_TOKEN` | появляется автоматически при подключении Blob-хранилища к проекту |

Публичный ключ также зашит в `src/lib/push.ts` (он не секрет — уходит в браузер по протоколу),
приватный ключ в репозитории не хранится.

Сгенерировать пару ключей:

```bash
npx web-push generate-vapid-keys --json
```

### Планировщик

`vercel.json` регистрирует ежедневный запуск `/api/cron` в 06:00 UTC (09:00 по Калининграду).
На плане Hobby это максимум — Vercel отклоняет более частые расписания. Чтобы уведомления приходили
точнее, тот же endpoint можно дёргать внешним планировщиком (cron-job.org и подобные) раз в 15–60 минут:

```bash
curl -H "Authorization: Bearer $CRON_SECRET" https://dmb-timer.vercel.app/api/cron
```

Ничего не дублируется: обработка идемпотентна, уже отправленные события повторно не уходят.

### Приватность

На сервер уходят только имя, даты службы, часовой пояс и подписка устройства — этого достаточно,
чтобы отправить напоминание. Хранится в приватном Blob-хранилище (доступ только по токену проекта).
Выключение уведомлений удаляет запись. Остальные данные приложения по-прежнему живут только
в `localStorage` устройства.



## Деплой

Проект живёт в монорепозитории [`MarkusFarfall/apps`](https://github.com/MarkusFarfall/apps) в папке `projects/dmb-timer`
и разворачивается отдельным проектом на Vercel: **Root Directory** = `projects/dmb-timer`, фреймворк — Vite.
Каждый push в `main`, затрагивающий эту папку, обновляет прод автоматически.
